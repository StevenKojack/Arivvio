# Showcase Marketplace release

Starting canonical main: `c3729bc3d6f778cc678101ae70372d1a8007387f`.

## Composition and configuration

The old loader replaced the entire Demo catalogue as soon as Supabase returned any providers. The new shared composition layer combines sourced businesses and 48 curated fictional examples. `NEXT_PUBLIC_MARKETPLACE_MODE` accepts `showcase` (default), `real`, or `demo`. A `mode` query parameter selects a presentation explicitly. This setting changes discovery, never database authorization.

The source registry centralizes status classification, routing, source-qualified identity, ranking and discovery groups. Canonical real identities retain business/service UUIDs. Negative numeric compatibility handles are deterministic within the loaded catalogue, collision-checked, and separate from positive Demo IDs. Restored cloud cart entries resolve by UUID, never by an old numeric hash.

Cards, profiles, maps and carts use Fictional Demo Provider, Unclaimed Business, Verified Business, or Business-Managed · Verification Pending. Authority verification is not a service guarantee. Listing type works inside the existing hard-filter pipeline. Real results with unknown schedules are evaluated separately from illustrative schedules so Demo exact matches cannot suppress them. Relevant verified results precede relevant unclaimed results and Demo examples. Hard service, event, capacity, language, location and eligibility requirements remain decisive.

## Inventory and presentation

48 public fictional examples reuse existing fixtures and packages. Legacy fixture IDs remain available for restored Demo continuity. Former real names in static fixtures were replaced with fictional identities, public street addresses removed, and external business URLs replaced by the Demo route. Synthetic ratings/review counts are zero and are not displayed. Coverage includes venues, food, music, photography/video, florals, rentals, desserts, entertainment, transport, staffing, security, AV and specialty services.

Five taxonomy-driven sections provide discovery rhythm. Existing responsive cards, premium styling, category imagery, image fallbacks and profile packages remain. Generic imagery is labeled illustrative. Only fixed-location venues with known coordinates receive pins. Fictional venue map details disclose their illustrative location. Traveling providers remain discoverable through lists and service areas.

## Request and continuity safety

Fictional selections use local Demo requests and responses. They never create Supabase requests or bookings. Demo carts are isolated by saved-event ID. Real cart records continue using canonical business/service UUIDs and existing backend checks. Real and Demo submissions have separate groups and review buttons, per-item source labels, estimates and fee disclosures. A real request needs an authenticated active saved event and persisted cart records.

Unclaimed businesses use the existing concierge route, with event ID preserved in profile links. Pending verification never permits a direct request. Verified businesses use the existing real request/conversation/quote/booking flow. No verification, membership, RLS, privacy or schema changes were made. No migrations are required.

Saved-event explicit service selections are preserved after event-preset initialization. Demo estimates remain illustrative. Empty real schedules are unknown, not available. Unconfirmed pricing remains Contact for pricing. No payment is collected.
